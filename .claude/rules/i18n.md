## i18n: English and Spanish

Moved from CLAUDE.md (2026-11-26). CLAUDE.md "Start here" step 5 keeps the one-line rule.

- Every new student-facing shell string goes in `i18n.js` (its header explains the wiring: `data-i18n` / `t()` +
  `data-i18n-params`) in BOTH `en` and `es`, same edit; never English-only. Module text gets `_es`; Journey pages
  `data-es`. Reuse its glossary.
- String names are solfège (`cuerda Mi grave`); chord symbols and keys are not (`tonalidad de G`, `G/B`). No check
  enforces the solfège rule: check it by eye whenever you touch module Spanish.
- The code is the authoritative Spanish: no review sheet; no proofread sweeps unless asked.
- Glossary, loanword policy and settled ES terms: `claude/spanish-terminology.md` in the Claude project (not in this
  repo).
- `i18n.js` loads before the `app/*.js` parts, `fab-tools.js`, `tuner.js`, `tabs/journey.js`.
- **1dp only reports:** it warns when an English string changes and its Spanish twin does not (`tools/i18n-drift.mjs`).
  Read each line it prints; a line printed in full is a changed fact, order or meaning. Removing twins on purpose (a
  Journey page, a game's strings) also lowers `DRIFT_FLOOR` in `tools/checks.mjs` (1dp) to the new count, as a
  pin-only edit in the same commit.
